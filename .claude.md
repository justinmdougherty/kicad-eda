# Project Context — dougherty-eda / kicad-eda

> Project context for all agents working in this repo. Keep it in sync with
> the server's real tool surface (`kicad-eda/server/kicad_server.py`).

## What This Is

A **Claude Code plugin marketplace** containing one plugin: **kicad-eda** — a
concept-to-Gerbers PCB design assistant for **KiCad 9/10**, using the **KiCad 11
IPC API** (nightly, optional) for the schematic: KiCad places the symbols and
writes the file, headless or live in its editor, instead of hand-written
S-expressions. This repo is *tooling for Claude Code itself*, not an
application: a Python MCP server plus the script toolchain it shells into,
Markdown skill/agent/command definitions, and Node hooks.

Two workflows:

- **Headless pipeline** (primary): `netlist.json` → schematic + ERC → SWIG
  board build → Freerouting → DRC → fab zip, through five self-remediating
  gates (`pipeline/run_pipeline.py`, IEEE 15288.2 style).
- **GUI-assisted 10-stage flow** (`skills/pcb-design`): MCP schematic tools
  (API or file backend), then live PCB edits over the KiCad IPC API with the
  board open in Pcbnew.

## Architecture

**MCP server (`server/kicad_server.py`, FastMCP name `kicad-generator`)** —
about 45 tools in three groups:

- **Schematic (two backends, one dispatch path, every response carries
  `backend: "api" | "file"`)**: `create_schematic(path, paper, backend="auto")`,
  `load_schematic(path, backend)`, `close_schematic`, `add_component` /
  `add_components_batch`, `add_wire` / `add_label` / `add_power_port` /
  `add_junction` (explicit coordinates), `wire_by_ref` = `wire_pins` /
  `label_pin` / `power_pin` / `no_connect_pin` (by ref + pin), `list_symbols`
  / `list_nets` / `schematic_netlist` (`{net: [[ref, pin]]}`), `save_schematic`,
  `run_erc` (newest kicad-cli on the saved file), `render_sch`.
  - `api` (`server/backends/sch_api.py`, when `kicad_env.pick_api()` finds a
    KiCad ≥ 10.99 and the vendored kipy imports): a per-path `Session` holds a
    `SchematicApi` — **headless** (a private `kicad-cli api-server`, ONE
    document at a time: opening another path drops an idle session and
    reports `released_sessions`, refuses while it is dirty) or **gui** (the
    file is open in a running KiCad 11 with its API enabled; edits land in the
    editor). Pin coordinates come from KiCad for any rotation/mirror;
    `load_schematic` really round-trips; Value/Footprint are deferred to the
    next read/save so repeated lib_ids stay linked to their library. Writes
    KiCad 11 files.
  - `file` (`server/sch_file_model.py`, same method surface): the in-memory
    model, symbols from the newest install's libraries, pin offsets from the
    symbol or a `server/pins/<Lib_Symbol>.pins.json` sidecar (42 shipped,
    `build_pin_sidecars` makes more); `load_schematic` does NOT parse the file.
- **PCB over IPC (`server/pcb_ipc_tools.py`, `kicad_ipc.connect()`)**:
  `test_kicad_connection` (open documents, version-derived `capabilities`,
  installs, `schematic_backend`), `get_pcb_summary`, `add_footprints_batch` /
  `move_footprint` / `add_footprint_to_pcb` (these POSITION footprints — on
  KiCad 9/10 only Update PCB from Schematic (F8) can create them),
  `remove_footprint`, `get_footprint_pads`, `register_net`, `add_trace` /
  `add_via` / `add_copper_zone`, `validate_placement`, `create_pcb` (bundled
  Python). Every one returns `{"ipc_connected": false, ...}` when KiCad is
  unreachable; there is no non-IPC fallback for live edits.
- **Headless pipeline (`server/board_pipeline_tools.py`, shell-outs to
  `server/tools/`)**: `build_schematic_from_netlist(..., backend="auto")` (API
  `build_from_netlist` when available, else `sch_build.py`; same topology, ERC
  via the newest kicad-cli), `design_report`, `build_board_from_netlist`,
  `check_design_gates`, `autoroute_board`, `add_ground_stitching`, `drc_pcb`,
  `export_gerbers`, `export_fab_package`, `render_pcb`, `server_status`
  (`installs`, `schematic_backend`, `api_kicad_version`, `kicad_cli_schematic`,
  `kicad_cli_board`, `kicad_cli_policy`, `schematics_open`).

**Open-document guard (`kicad_ipc.write_guard`):** the writers (`save_schematic`,
`create_schematic`, `build_schematic_from_netlist`, `build_board_from_netlist`,
`autoroute_board`, `add_ground_stitching`) refuse to overwrite a file listed in
`open_documents` and return `{"ok": false, "reason": ...}`; unknown (IPC down)
never blocks. **Exception:** a schematic open in a KiCad 11 GUI is edited
through it (`load_schematic` → `mode: "gui"`, `save_schematic` saves there);
KiCad 9/10 editors and every board write keep the refusal. Read-only tools
(`drc_pcb`, `render_*`, `export_*`) work on the saved file.

**Orchestration:** `pcb-design` is the lead engineer for the GUI flow — a
strict 10-stage gated workflow that delegates each gate review to a subagent
and refuses to advance while a BLOCKER stands:

| Stage | Gate reviewer (subagent) | Model / tools |
|---|---|---|
| 2 — Parts selection | `parts-selector` | sonnet, can write |
| 4–5 — ERC / Critical Design Review | `erc-reviewer` | sonnet, **read-only** |
| 7 — Placement | `placement-reviewer` | sonnet, **read-only** |
| 9 — DRC | `drc-reviewer` | sonnet, **read-only** |
| 10 — Fab output | `fab-checker` | sonnet, **read-only** |

`netlist-pipeline` + `/pipeline` drive the headless flow through
`run_pipeline.py` (G1 lint → G2 sch+ERC → G3 placement → G4 route+DRC → G5 fab
zip) with auto-remediation between gates; the same steps exist as MCP tools.
`run_pipeline.py` calls `k.build_schematic_from_netlist` unchanged — the
backend choice is invisible to it apart from `report["schematic"]["backend"]`.

**Vendored kipy (`server/vendor/`):** kicad-python `main` 0.9.0.dev0 with
protobufs generated from KiCad master `api/proto` (origin JSON in
`server/vendor/README.md`); `kicad_env.use_vendored_kipy()` puts it first on
`sys.path` before any `import kipy`. Refresh with
`server/tools/update_kipy.py` (clone → fetch protos → temp venv with
`protoc-wheel-0==29 protoletariat==3.3.* mypy-protobuf==3.6.*` → generate →
rewrite `from common|board|schematic… import` to `from kipy.proto.…` → vendor).

**Hooks (`hooks/hooks.json` → `scripts/hook.js`):** `session-start` prints the
environment report (KiCad, Java, venv); `check-ipc` is a PreToolUse gate on
the IPC tools (probes the API through the server venv with kipy
`get_version`; allows on ok/unknown, falls back to a kicad/pcbnew process
scan only when kipy is absent, exit 2 otherwise);
`validate-schematic` is a PostToolUse structural check of every `.kicad_sch`
write (exit 2 on corruption so the model regenerates from clean state).

## Build / Test / Run

```bash
claude plugin validate ./kicad-eda --strict            # manifest, frontmatter, hooks
claude plugin details kicad-eda                        # component inventory + token cost
kicad-eda/.venv/Scripts/python.exe kicad-eda/server/kicad_server.py            # server standalone
kicad-eda/.venv/Scripts/python.exe kicad-eda/pipeline/run_pipeline.py <netlist.json> <w> <h>
kicad-eda/.venv/Scripts/python.exe kicad-eda/pipeline/run_all.py               # regression matrix (~150 min)
cd kicad-eda && .venv/Scripts/python.exe -m pytest -q                          # unit tier + live API tier (skips without KiCad 11)
kicad-eda/.venv/Scripts/python.exe kicad-eda/server/kicad_env.py               # print every KiCad install found
```

`tests/test_sch_api.py` shares one headless api-server per module (~6 s
library load) and closes every document in teardown — no `kicad-cli.exe` may
outlive a run. `tests/test_server_dispatch.py` monkeypatches the API away and
proves the file-backend fallback (`backend: "file"`).

CI (`.github/workflows/regression.yml`) runs `run_all.py` in the official
`kicad/kicad:10.0` container on pushes to `main` / `improvements` and on PRs,
uploading failed boards as artifacts. End-user install:
`/plugin marketplace add justinmdougherty/kicad-eda`,
`/plugin install kicad-eda@dougherty-eda`, then `/kicad-eda:setup`.

## Conventions

- **Python:** PEP 8, type annotations, `from __future__ import annotations`.
  Server tools are `@mcp.tool()` functions returning a dict with an `ok` /
  `ipc_connected` status; errors raise `ValueError` with actionable messages
  or return `{"ok": false, "reason": ...}`; backend failures
  (`SchematicApiError`, `ValueError` from the file model) become
  `{"ok": false, "backend", "reason"}` through `_dispatch`. Never swallow
  exceptions silently. Scripts under `server/tools/` print their result as the
  LAST stdout line in JSON (`toolchain.last_json` parses it). Small focused
  files (`kicad_server.py` is at the 800-line cap — add tool families beside
  it, not inside it), immutable patterns.
- **Toolchain:** never resolve `kicad-cli` / the bundled Python / library dirs
  ad hoc — go through `toolchain.py` (`kicad_cli()`, `kicad_python()`,
  `symbols_dir()`, `footprints_dir()`), which applies the per-job rules in
  `kicad_env`. Import `kipy` only after `kicad_env.use_vendored_kipy()` (the
  server and `kicad_ipc` do it at import time; `backends/kipy_bridge` is the
  guarded import every backend module uses).
- **Hooks:** Node, cross-platform; non-fatal where KiCad is optional (exit 0
  with a warning), blocking (exit 2) only on real guardrail violations.
- **Skill/agent/command frontmatter:** `name`, `description` (with an explicit
  "Use when…" trigger), and for agents `model`, `effort`, `maxTurns`,
  `disallowedTools`. Prompts may name only tools that exist in the server.
- **KiCad engineering conventions** are codified in `SKILL.md` to IEC 61082 /
  IEC 81346 / IEEE 315: left-to-right signal flow, top-to-bottom power,
  orthogonal wires, junction-dot rules, ALL_CAPS net names, standard refdes
  prefixes. Treat these as hard rules when editing the skill.
- **Pipeline contract:** `pipeline/run_pipeline.py`, `run_all.py`, `examples/`
  and the regression results are the compatibility contract — tool changes
  must keep the success path identical.

## Key Risks & Technical Debt

- **KiCad 9/10 IPC cannot create footprints** — the GUI flow depends on the
  user's F8 import; KiCad 11's `capabilities.place_footprint_from_library` /
  `import_netlist` are reported but their tool surface is not built yet
  (the `schematic_api` capability IS: the schematic backend). Prompts must
  not invent the board-side tools.
- **The API backend tracks a nightly.** KiCad 10.99 protos change; the
  vendored kipy is pinned to a KiCad-master commit (`server/vendor/README.md`)
  and a newer nightly may need `update_kipy.py`. Known 10.99 quirk worked
  around in `sch_items.prime_definition` / deferred fields: `UpdateItems`
  blanks the embedded symbol's Description and re-placing the same lib_id
  then forks a renamed private copy (`R_1`).
- **KiCad 11 files are one-way** — anything the API backend saves needs
  KiCad 11 (and its kicad-cli) to open; `backend="file"` keeps 9/10 format.
- **Three schematic emitters** — the API backend, the file model
  (`sch_file_model.py`, interactive tools) and `tools/sch_build.py` (pipeline
  fallback). The two file writers share the emitter format; the API and
  `sch_netlist_build` must keep the same topology as `sch_build` so ERC
  results match. Prefer `build_schematic_from_netlist` for anything real.
- **`load_schematic` round-trips only on the API backend** — the file model
  registers an empty model and `save_schematic` REPLACES the file.
- **Headless api-server holds one document** — sessions are released (saved)
  or refused (dirty) when another path is opened; the responses say so.
- **`check-ipc` hook probes the API, not the file** — it gates only the live
  board tool family (allows on ok/unknown, process scan only without kipy);
  the server-side open-document guard is the real protection for writes.
- **Pin sidecars are trusted blindly (file backend)** — a
  `server/pins/*.pins.json` file overrides the symbol-derived offsets without
  being validated against the library, so a stale or hand-edited sidecar
  silently mis-wires by ref. The API backend does not use them.
- **Freerouting is non-deterministic** and 1.9 cannot neck down —
  `autoroute_board` may leave stubs (re-run until `unconnected` is 0); see the
  traps list in `docs/PIPELINE.md`.
- **The live API tests need the machine's nightly** — `tests/test_sch_api.py`
  skips without one, so CI (KiCad 10 container) never exercises the API
  backend; the 150-minute regression matrix stays the real gate for boards.
