## What This Is

A **Claude Code plugin marketplace** containing one plugin: **kicad-eda** — an
end-to-end PCB design assistant for **KiCad 9** that drives a design from a
one-line concept through to fab-ready Gerbers. This repo is *tooling for Claude
Code itself*, not an application. The "code" is a small Python MCP server plus a
set of Markdown skill/agent/command definitions and shell/Python hooks.

## Architecture

**The MCP server (`server/kicad_server.py`)** has two tool layers:

- **SCHEMATIC layer** — pure-Python `.kicad_sch` S-expression generation. No
  KiCad required. Fully functional; produces files that open in KiCad 9.
  Tools: `create_schematic`, `add_components_batch`, `wire_by_ref`, `label_pin`,
  `power_pin`, `run_erc`, `render_sch`, etc.
- **PCB layer** — KiCad 9 IPC API via `kipy`. Requires KiCad running with the
  API server enabled. When unreachable, every PCB tool returns
  `{"ipc_connected": false, ...}` so the workflow stops cleanly.
  Tools: `create_pcb`, `add_footprints_batch`, `add_trace`, `add_via`,
  `export_gerbers`, `drc_pcb`, etc.

**Two documented drop-in points** (server is a clean baseline, not the mature
generator): (1) full `lib_symbols` embedding, and (2) the pin-coordinate sidecar
at `server/pins/<Library_Symbol>.pins.json` that powers `wire_by_ref` /
`label_pin` / `power_pin`. Absent a pin map, those tools raise explicitly rather
than guessing coordinates.

**Orchestration model:** the `pcb-design` skill is the lead engineer and runs a
strict **10-stage gated workflow**. At each gate it delegates review to a
matching subagent and refuses to advance while a BLOCKER stands:

| Stage | Gate reviewer (subagent) | Model / tools |
|---|---|---|
| 2 — Parts selection | `parts-selector` | sonnet, can write |
| 4–5 — ERC / Critical Design Review | `erc-reviewer` | sonnet, **read-only** |
| 7 — Placement | `placement-reviewer` | sonnet, **read-only** |
| 9 — DRC | `drc-reviewer` | sonnet, **read-only** |
| 10 — Fab output | `fab-checker` | sonnet, **read-only** |

Reviewer agents have `disallowedTools: Write, Edit` — they report findings
(BLOCKER / RISK / NOTE), the main thread fixes.

**Three guardrail hooks (`hooks/hooks.json`):**

- `SessionStart` → `bootstrap-env.sh`: builds/refreshes the server venv in
  `${CLAUDE_PLUGIN_DATA}` (persists across plugin updates), reinstalls deps only
  when `requirements.txt` changes, verifies `kicad-cli` is on PATH.
- `PreToolUse` (PCB tools) → `check-ipc.sh`: blocks PCB tool calls (exit 2) when
  no running KiCad process is detected — prevents the file-corruption path that
  bit earlier text-based builds.
- `PostToolUse` (schematic writes) → `validate-schematic.py`: fast structural
  check of the `.kicad_sch` (balanced parens, valid top token, non-empty);
  exits 2 on a clear corruption so the model regenerates from clean state.

## Conventions

- **Python:** PEP 8, type annotations, `from __future__ import annotations`.
  Server uses `@mcp.tool()` decorators; every tool returns a dict (often with an
  `ok` / `ipc_connected` status field). Errors raise `ValueError` with
  actionable messages. Per global rules: prefer small focused files, immutable
  patterns, comprehensive error handling.
- **Bash hooks:** `set -euo pipefail`, non-fatal where KiCad is optional (exit 0
  with a warning), blocking (exit 2) only on real guardrail violations.
- **Skill/agent frontmatter:** `name`, `description` (with explicit "Use
  when…" trigger), and for agents `model`, `effort`, `maxTurns`,
  `disallowedTools`.
- **KiCad engineering conventions** are codified in `SKILL.md` to IEC 61082 /
  IEC 81346 / IEEE 315: left-to-right signal flow, top-to-bottom power,
  orthogonal wires, junction-dot rules, ALL_CAPS net names, standard refdes
  prefixes. Treat these as hard rules when editing the skill.

## Key Risks & Technical Debt

- **Not a git repository** — no version history, branches, or commit log. If
  this is meant to ship from `github.com/dougherty-labs/kicad-eda`, run
  `git init` and establish history.
- **Server PCB layer is a baseline, not complete** — `add_footprint_to_pcb`,
  `add_trace`, `move_footprint`, `get_footprint_pads`, `drc_pcb` etc. return
  `note` placeholders ("implement against your KiCad 9 kipy version"). The IPC
  write path is structurally present but not wired to real `kipy` commits.
- **`load_schematic` does not round-trip** — registers a fresh model instead of
  parsing the file; marked as a drop-in point.
- **Pin sidecars absent** — `wire_by_ref`/`label_pin`/`power_pin` raise until
  `server/pins/*.pins.json` maps exist. No sidecars are shipped.
- **SKILL.md references tools not in the baseline server** —
  `test_kicad_connection`, `finalize_schematic`, `get_pin_positions`,
  `populate_lib_symbols`, `define_custom_symbol`, `route_pcb` are named in the
  skill/agents but not defined in `kicad_server.py`. Reconcile names before
  release.
- **Cross-platform hooks** — hooks are Bash + `python3`. On this Windows host,
  `bootstrap-env.sh` (`${VENV}/bin/python`, `pgrep`) assumes a POSIX layout;
  verify the plugin runs hooks under Git Bash / WSL or port to `.ps1`.
- **No tests / no CI** — global rules target 80% coverage; none exists here.
