## What This Is

A **Claude Code plugin marketplace** containing one plugin: **kicad-eda** — a
concept-to-Gerbers PCB design assistant for **KiCad 9/10**, with the **KiCad 11
IPC API** as the forward path for live editing. This repo is *tooling for
Claude Code itself*, not an application: a Python MCP server plus the script
toolchain it shells into, Markdown skill/agent/command definitions, and Node
hooks.

Two workflows:

- **Headless pipeline** (primary): `netlist.json` → schematic + ERC → SWIG
  board build → Freerouting → DRC → fab zip, through five self-remediating
  gates (`pipeline/run_pipeline.py`, IEEE 15288.2 style).
- **GUI-assisted 10-stage flow** (`skills/pcb-design`): MCP schematic tools,
  then live PCB edits over the KiCad IPC API with the board open in Pcbnew.

## Architecture

**MCP server (`server/kicad_server.py`, FastMCP name `kicad-generator`)** —
about 40 tools in three groups:

- **Schematic (in-memory model → `.kicad_sch`)**: `create_schematic`,
  `load_schematic`, `add_component` / `add_components_batch`, `add_wire` /
  `add_label` / `add_power_port` (explicit coordinates), `wire_by_ref` /
  `label_pin` / `power_pin` (coordinates derived from the KiCad symbol and
  rotated by the symbol's `rot`; a sidecar in
  `server/pins/<Lib_Symbol>.pins.json` overrides — 42 shipped,
  `build_pin_sidecars` makes more), `list_symbols` / `list_nets`, `save_schematic`, `run_erc`,
  `render_sch`. Needs no running KiCad; ERC/render use kicad-cli.
- **PCB over IPC (`_kipy()`)**: `test_kicad_connection` (reports
  `open_documents` and version-derived `capabilities`), `get_pcb_summary`,
  `add_footprints_batch` / `move_footprint` / `add_footprint_to_pcb` (these
  POSITION footprints — on KiCad 9/10 only Update PCB from Schematic (F8) can
  create them), `remove_footprint`, `get_footprint_pads`, `register_net`,
  `add_trace` / `add_via` / `add_copper_zone`, `validate_placement`. Every one
  returns `{"ipc_connected": false, ...}` when KiCad is unreachable; there is
  no non-IPC fallback for live edits.
- **Headless pipeline (shell-outs to `server/tools/`)**: `create_pcb` (bundled
  Python, empty board file), `build_schematic_from_netlist`, `design_report`,
  `build_board_from_netlist`, `check_design_gates`, `autoroute_board`,
  `add_ground_stitching`, `drc_pcb`, `export_gerbers`, `export_fab_package`,
  `render_pcb`, `server_status`.

**Open-document guard:** the writers (`save_schematic`,
`build_schematic_from_netlist`, `build_board_from_netlist`, `autoroute_board`,
`add_ground_stitching`) refuse to overwrite a file listed in `open_documents`
and return `{"ok": false, "reason": ...}`; unknown (IPC down) never blocks.
Read-only tools (`drc_pcb`, `render_*`, `export_*`) work on the saved file.

**Orchestration:** `pcb-design` is the lead engineer for the GUI flow — a
strict 10-stage gated workflow that delegates each gate review to a subagent
and refuses to advance while a BLOCKER stands:

| Stage | Gate reviewer (subagent) | Model / tools |
|---|---|---|
| 2 — Parts selection | `parts-selector` | sonnet, can write |
| 4–5 — ERC / Critical Design Review | `erc-reviewer` | sonnet, **read-only** |
| 7 — Placement | `placement-reviewer` | sonnet, **read-only** |
| 9 — DRC | `drc-reviewer` | sonnet, **read-only** |
| 10 — Fab output | `fab-checker` | sonnet, **read-only** |

`netlist-pipeline` + `/pipeline` drive the headless flow through
`run_pipeline.py` (G1 lint → G2 sch+ERC → G3 placement → G4 route+DRC → G5 fab
zip) with auto-remediation between gates; the same steps exist as MCP tools.

**Hooks (`hooks/hooks.json` → `scripts/hook.js`):** `session-start` prints the
environment report (KiCad, Java, venv); `check-ipc` is a PreToolUse gate on
the IPC tools (probes the API through the server venv with kipy
`get_version`; allows on ok/unknown, falls back to a kicad/pcbnew process
scan only when kipy is absent, exit 2 otherwise);
`validate-schematic` is a PostToolUse structural check of every `.kicad_sch`
write (exit 2 on corruption so the model regenerates from clean state).

## Build / Test / Run

```bash
claude plugin validate ./kicad-eda --strict            # manifest, frontmatter, hooks
claude plugin details kicad-eda                        # component inventory + token cost
kicad-eda/.venv/Scripts/python.exe kicad-eda/server/kicad_server.py            # server standalone
kicad-eda/.venv/Scripts/python.exe kicad-eda/pipeline/run_pipeline.py <netlist.json> <w> <h>
kicad-eda/.venv/Scripts/python.exe kicad-eda/pipeline/run_all.py               # regression matrix (~150 min)
kicad-eda/.venv/Scripts/python.exe -m pytest kicad-eda                         # unit tests (pytest-cov installed)
```

CI (`.github/workflows/regression.yml`) runs `run_all.py` in the official
`kicad/kicad:10.0` container on pushes to `main` / `improvements` and on PRs,
uploading failed boards as artifacts. End-user install:
`/plugin marketplace add justinmdougherty/kicad-eda`,
`/plugin install kicad-eda@dougherty-eda`, then `/kicad-eda:setup`.

## Conventions

- **Python:** PEP 8, type annotations, `from __future__ import annotations`.
  Server tools are `@mcp.tool()` functions returning a dict with an `ok` /
  `ipc_connected` status; errors raise `ValueError` with actionable messages
  or return `{"ok": false, "reason": ...}`. Never swallow exceptions silently.
  Scripts under `server/tools/` print their result as the LAST stdout line in
  JSON (`_last_json` parses it). Small focused files, immutable patterns.
- **Hooks:** Node, cross-platform; non-fatal where KiCad is optional (exit 0
  with a warning), blocking (exit 2) only on real guardrail violations.
- **Skill/agent/command frontmatter:** `name`, `description` (with an explicit
  "Use when…" trigger), and for agents `model`, `effort`, `maxTurns`,
  `disallowedTools`. Prompts may name only tools that exist in the server.
- **KiCad engineering conventions** are codified in `SKILL.md` to IEC 61082 /
  IEC 81346 / IEEE 315: left-to-right signal flow, top-to-bottom power,
  orthogonal wires, junction-dot rules, ALL_CAPS net names, standard refdes
  prefixes. Treat these as hard rules when editing the skill.
- **Pipeline contract:** `pipeline/run_pipeline.py`, `run_all.py`, `examples/`
  and the regression results are the compatibility contract — tool changes
  must keep the success path identical.

## Key Risks & Technical Debt

- **KiCad 9/10 IPC cannot create footprints** — the GUI flow depends on the
  user's F8 import; KiCad 11 (`capabilities.place_footprint_from_library`,
  `schematic_api`, `import_netlist`) is the forward path and its tool surface
  is not built yet. Prompts must not invent it.
- **Two schematic emitters** — the server's in-memory `save_schematic` path and
  `tools/sch_build.py` (the pipeline's, richer). Prefer
  `build_schematic_from_netlist` for anything real; keep both in sync.
- **`load_schematic` does not round-trip** — it registers a fresh model
  instead of parsing the file.
- **No MCP no-connect tool** — GUI-flow schematics leave unused pins as ERC
  "not connected" unless the user adds NC flags in Eeschema after the last
  save, or the netlist path is used.
- **`check-ipc` hook probes the API, not the file** — it gates only the IPC
  tool family (allows on ok/unknown, process scan only without kipy); the
  server-side open-document guard is the real protection for writes.
- **Pin sidecars are trusted blindly** — a `server/pins/*.pins.json` file
  overrides the symbol-derived offsets without being validated against the
  library, so a stale or hand-edited sidecar silently mis-wires by ref.
- **Freerouting is non-deterministic** and 1.9 cannot neck down —
  `autoroute_board` may leave stubs (re-run until `unconnected` is 0); see the
  traps list in `docs/PIPELINE.md`.
- **Test coverage is thin** — the 150-minute regression matrix is the real
  gate; unit tests are new and small.
